# Кейс для портфолио: кабинет обработки обращений

## Задача

Показать сценарий автоматизации поддержки вымышленного интернет-магазина: обращения по разным темам поступают в общий список, сотрудник определяет их тип и готовит ответ. Требуется сократить ручную подготовку черновика, сохранив проверку человеком. Фактическая экономия времени в этом проекте не измерялась.

## Требования

- Принимать обращение через API и интерфейс.
- Разделять запросы на доставку, возврат, товар и прочие вопросы.
- Готовить редактируемый ответ без выдуманных сведений о заказе.
- Подтверждать результат вручную, сохранять историю обработки.
- Обеспечить воспроизводимый запуск на вымышленных данных.

## Решения

Python и SQLite позволяют запустить проект без сторонних зависимостей. Интерфейс состоит из списка обращений и карточки с сообщением, категорией и черновиком. Статусы отделяют новую заявку от подготовленного и подтверждённого ответа. В модели нет инструментов, которые могут отправлять сообщения или выполнять действия с заказами.

Предусмотрены два явно различимых режима. DEMO применяет правила и шаблоны, чтобы проект можно было проверить без ключа. LLM-адаптер передаёт сообщение настроенному провайдеру и проверяет структуру ответа. При сбое провайдера данные сохраняются, сотрудник видит ошибку.

## Что реализовано и проверено

Работающий локальный кабинет, JSON API, хранение заявок и событий, поиск, фильтры, демо-примеры, редактирование и подтверждение. Автотесты проверяют жизненный цикл, ограничения состояний, входные данные и ошибки интеграции. Живой вызов платной модели не выполнялся.
